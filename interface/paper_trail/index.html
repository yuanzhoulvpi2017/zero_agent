采集→数据→训练→评测

要解决的问题

从原始轨迹里选出可用于 SFT 的轮次：去掉失败、空转和泄密，补人工偏好，并划出独立测试集。

输入

  • data/paper_trail/web/<session_id>/trajectory.json
  • manifest.json 中的模型、配置与用量

输出

  • 新实验目录，不覆盖旧会话
  • 标注结果、划分清单、SFT jsonl
  • 更新后的 manifest.json 数据集字段

本页将提供

  1. 按状态 / 工具正确性过滤轨迹
  2. 逐轮标注：保留、改写、丢弃
  3. 训练 / 测试划分，测试任务不进训练
  4. 导出 SFT 样本并记录版本

训练任务

训练入口与导出。实现放在 training/paper_trail/，界面只提交任务和展示状态。

采集→数据→训练→评测

要解决的问题

在独立训练环境中，用已划分的 SFT 数据微调基座模型，并导出可供 Agent 接入的权重。

输入

  • 数据集版本与路径（来自筛选标注）
  • 基座模型、超参与提交号

输出

  • data/paper_trail/ 下的权重，不提交 Git
  • 训练日志；manifest 的 training 字段，未跑完不填虚构结果

本页将提供

  1. 选择数据集版本并启动训练
  2. 查看进度、损失与中断原因
  3. 导出后登记，供评测页选用

效果对比

评测计算放在 evaluation/paper_trail/。对比时尽量固定测试任务、工具、提示词和执行限制。

采集→数据→训练→评测

要解决的问题

用同一套测试任务比较商业模型、未训练基座和 SFT 模型接入小埋后的效果，并写清指标怎么算。

输入

  • 预留测试集，不进入训练数据
  • 待测模型端点（商业 / 基座 / SFT）
  • 与采集阶段一致的工具与系统提示

指标

  • 任务成功率
  • 工具调用正确率
  • 耗时与 Token 成本

本页将提供

  1. 批量跑测试任务并保存报告
  2. 并排对比三次接入的差异
  3. 记录配置差异，避免 Implicit 换工具或提示词
