# 业务开发指南

本仓库按阶段组织代码，在各阶段下使用相同的业务名（小写英文加下划线）。按实际进度新增业务目录，无需提前创建空业务。

## 目录约定

| 目录 | 内容 |
| --- | --- |
| `agent/<业务名>/` | Agent、自定义工具、轨迹采集 |
| `dataset/<业务名>/` | 轨迹清洗、过滤、标注、SFT 数据生成 |
| `training/<业务名>/` | 模型训练和导出 |
| `evaluation/<业务名>/` | 推理、评测和效果对比 |
| `interface/<业务名>/` | 统一用户交互界面与后端调用适配 |
| `configs/<业务名>/` | 各阶段配置 |
| `docs/<业务名>/` | 业务总入口与阶段教程 |
| `data/<业务名>/` | 轨迹、缓存、数据集、权重和报告，不提交 Git |

## 新增一个业务

1. 创建 `docs/<业务名>/README.md`，说明业务目标、任务示例、各阶段代码链接和进度。
2. 从 `agent/<业务名>/` 开始实现，后续逐步增加数据处理、训练和评测模块；用户交互界面统一放在 `interface/<业务名>/`，可随任一阶段开发。
3. 按阶段编写 `01_agent.md`、`02_dataset.md`、`03_training.md`、`04_evaluation.md`，界面说明放在 `05_interface.md`（编号不限制开发顺序）。每篇写明解决的问题、输入输出格式、环境准备、运行命令和预期结果，任务用勾选清单跟踪。
4. 每次实验保存 `manifest.json`，记录代码提交、配置、轨迹批次、数据集版本、基座模型、训练产物和测试集版本。引用的产物需使用可追溯的路径或标识，避免覆盖旧实验。

## 依赖与复用

根目录现有 `pyproject.toml` 和 `uv.lock` 继续用于基础教程。新增 Python 阶段模块在首次引入可运行代码时，创建自己的 `pyproject.toml`、`uv.lock` 和虚拟环境，文档注明运行目录；训练环境独立管理。若同一阶段的业务依赖冲突，再为相关业务建立独立环境。

使用 AgentScope 的模块应声明 `agentscope>=1.0.18,<2.0.0`，避免升级到 2.x。跨阶段通过明确的数据格式或服务接口衔接；出现稳定的重复需求后，再在对应阶段增加 `common/`。

Git 提交和标签用于保存开发阶段版本，四个阶段的代码长期共存，支持反复采集、处理、训练和评测。

## 用户交互层

- 后续所有面向用户的交互界面统一放在 `interface/<业务名>/`，包括聊天、任务提交、轨迹浏览、数据标注、训练状态查看和评测结果展示，按实际需求实现。
- `interface/` 负责界面、交互状态和后端调用适配；Agent 执行与工具实现属于 `agent/`，数据处理属于 `dataset/`，训练属于 `training/`，模型推理服务和评测计算属于 `evaluation/`。界面调用这些模块提供的明确接口，不复制核心业务逻辑。
- 各阶段可以保留独立的脚本、批处理入口和服务接口；需要新增用户交互界面时统一放到 `interface/`。现有基础教程示例保持原有组织方式。
- 界面可随任一阶段开发，无需等待训练或评测完成。业务文档写明界面启动方式、依赖的后端服务、配置和接口约定。
- 界面依赖按所选技术栈独立管理：Python 界面使用自己的 `pyproject.toml` 和 `uv.lock`；JavaScript/TypeScript 界面使用 `package.json` 和对应锁文件。尚未选型时不预建框架或依赖。
