# PaperTrail 评测

本地 vLLM 推理，以及教师 flash / 未训 Qwen3.5-4B / SFT 4B 接入小埋后的同协议对比。业务说明见 [docs/paper_trail/04_evaluation.md](../../docs/paper_trail/04_evaluation.md)。

## 入口

| 文件 | 职责 |
| --- | --- |
| [serve_vllm.py](serve_vllm.py) / [serve_vllm.sh](serve_vllm.sh) | 在 3090 上提供 OpenAI 兼容接口。`MODEL_KIND=sft`（默认）或 `base` |
| [run_paper_trail_eval.py](run_paper_trail_eval.py) | 对比评测入口（走 interface 环境） |
| [compare_4b.py](compare_4b.py) | 虚拟人采集 + `deepseek-v4-flash` 打分 + 统计 |
| [scoring.py](scoring.py) | 自动指标与评委 JSON |

从仓库根目录：

```bash
# 只看 16 条人设
python evaluation/paper_trail/run_paper_trail_eval.py --dry-sample

# 完整对比（8 类 × 2 场 × 最多 10 轮；先 SFT 再基座；结束后恢复 SFT）
python evaluation/paper_trail/run_paper_trail_eval.py

# 给已有蒸馏轨迹里的教师 flash 打分（不重新对话，只评前 10 轮）
python evaluation/paper_trail/run_paper_trail_eval.py \
  --run-dir data/paper_trail/eval/<run_id> --skip-collect --skip-vllm-swap --score-teacher

# 评委输入改过之后，用已有轨迹重打分（不重新对话）
python evaluation/paper_trail/run_paper_trail_eval.py \
  --run-dir data/paper_trail/eval/<run_id> --skip-collect --skip-vllm-swap --rejudge

# 中断后续跑
python evaluation/paper_trail/run_paper_trail_eval.py --run-dir data/paper_trail/eval/<run_id>
```

轨迹与原始分数在 `data/paper_trail/eval/`（不提交 Git）。3090 同时只够挂一个 64k 实例。

## 三个维度

总分只平均这三维。先前八维等权有问题：身份经常没被问却占 1/8；「对象适配」和「有用」重复；不调工具会在工具使用和依据上各扣一次。

| 字段 | 中文 | 看什么 | 不看什么 |
| --- | --- | --- | --- |
| grounding | 依据 | 该查时查了没有、失败是否承认、具体信息在不在工具证据里 | 话多话少、乱码、自称小埋 |
| helpfulness | 有用 | 对方已经说出口的事帮到没有；当轮接得住，整场有推进 | 论文号在不在工具里；清单太长 |
| dialogue | 对话 | 含糊先问清、长短可控、接上文、少乱码、不倾泻清单 | 有没有编论文；帮没帮上忙 |

工具行为、明确 arXiv ID 核验、输出长度和身份场景只作诊断，不进总分。同一问题只进一维。

### 读表须知

1. **只有“依据 / 有用 / 对话”进入总分。** 后面的工具、ID、长度、告警和身份都只是诊断项。
2. **每个模型只有 16 场。** 这些数字用于定位问题，不是稳定排行榜。
3. **教师不是和 4B 逐句配对。** 教师复用旧蒸馏轨迹，只对齐角色类别、前 10 轮和评委；只有基座与 SFT 使用同一批 persona ID 计算配对胜负。
4. **工具多不代表更好。** “工具成功”只表示接口返回 `ok=true`，不表示工具选得对或最终答案正确。
5. **明确 ID 支持率不是完整事实正确率。** 它只核验回复里写出的 arXiv ID；无编号标题、作者、数字和仓库不在分母里。
6. **幻觉等告警是评委判断，不是自动事实。** 要结合明确 ID 核验和原轨迹阅读。
7. **不比较耗时。** 教师来自 10–12 轮旧轨迹，按比例折算与 4B 的 10 轮实测不公平。
8. **教师分数可能偏高。** 教师和评委都是 `deepseek-v4-flash`，可能存在同模型风格偏好；4.69 不是独立评委下的客观绝对分。

**教师 4.69，SFT 2.06，基座 1.90。实际情况是：**

- **教师高分来自这 16 场里的可观察行为：** 111 个明确 arXiv ID 全部能在工具结果中找到；工具结果成功率 99%；评委给 12/16 场依据 5 分、15/16 场有用 5 分。原轨迹里常见的是读不到就承认、用户要短就收短、最后给出可执行下一步。但教师与 4B 不是逐句配对，而且由同一个 flash 评审，分数可能有风格偏好，不能把 4.69 当作独立基准的绝对值。
- **SFT 高于基座主要是“更常查”，不是“事实更准”：** SFT 每场调用工具 9.3 次、12/16 场读过论文、仅 2/16 场被标该查未查；基座分别是 3.5 次、4/16 和 6/16，因此 SFT 的综合依据分高 0.50。反过来，SFT 明确 ID 支持率只有 71.4%，低于基座 78.9%，且两者都有 13/16 场幻觉告警；SFT 提得多，也多错。
- **“有用”差 0.19、“对话”差 −0.19 都很小：** 两项都只相当于 16 场里总共相差 3 个单点评分，不应解读成稳定胜负。SFT 虽然回复更短，但 15/16 场被标倾泻清单，并出现乱码和绕圈；短不等于会聊。
- **总分只说明本批样本：** SFT 对基座为 6 胜、3 负、7 平，属于轻微领先，不是训练已经成功解决了可靠性。确定学到的是工具行为；尚未学稳的是工具外不补细节和对话收敛。

### 明确 arXiv ID 核验（自动，不进总分）

只核验回复中明确写出的 arXiv ID，不能发现无编号的假标题、作者、数字和仓库。支持率按所有明确 ID 微平均：

`工具返回中出现过的回复 ID 数 ÷ 回复中的全部明确 ID 数`

| 指标 | 教师 | 基座 | SFT |
| --- | --- | --- | --- |
| 回复明确 ID 总数 | 111 | 19 | 91 |
| 工具内 / 工具外 ID | 111 / 0 | 15 / 4 | 65 / 26 |
| 明确 ID 支持率 | **100%** | 78.9% | 71.4% |
| 有工具外 ID 的场次 | **0/16** | 2/16 | 10/16 |

基座的 78.9% 不能说明它比 SFT 更可靠：基座只写了 19 个明确 ID，且无编号的编造不在这项统计里。
